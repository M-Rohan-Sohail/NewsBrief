1. Executive Summary & Strategic Pivot

The initial design of NewsBrief was conceived as a consumer-oriented AI news briefing mobile app, monetized via $4.99/month in-app subscriptions. However, market benchmarking and post-mortem analyses of high-profile failures (most notably Artifact by Instagram founders, which shut down and was acquired by Yahoo due to consumer news churn) reveal that standalone consumer news reading is a venture graveyard.

Market Reality Check
General news reading suffers from zero willingness-to-pay, high churn, and fierce competition from free alternatives (Twitter/X, Reddit, Perplexity, free email newsletters like TLDR). Selling a $4.99/mo consumer news reader is an uphill battle.

The Strategic Pivot: Rather than competing for personal recreation time, NewsBrief pivots to Autonomous Market & Competitor Intelligence for knowledge professionals (Founders, AI Engineers, Product Managers, and Investors). These users do not want "news"; they want strategic signal to ensure they are never blindsided in a board meeting, sprint planning, or investor update.

Core Pillars of the Redesign:

  • From Consumer to Prosumer / B2B: Re-position from casual reading to an indispensable work tool expensable on corporate software/learning budgets.
  • From Single Source to High-Signal Multi-Source: Escape Google News SEO spam by integrating Hacker News, GitHub Trending, arXiv preprints, and curated Substack RSS feeds alongside neural search (Exa.ai).
  • From Single Mobile App to Omnichannel Delivery: Deliver value where users actually work—7:00 AM Email Digest (primary retention anchor), 3-minute AI Audio Briefing (commute/gym), Slack Bot (team virality), and the Mobile App (lean-back deep dive reader).
  • From O(N) Redundant Scraping to Global Two-Stage Clustering: Separate global daily ingestion from user delivery to reduce LLM and scraping costs by over 90%.

3. Architecture & Workflow Overhaul

3.1 Current Flaws vs. New Architecture

The existing pipeline in backend/run_pipeline.py is tightly coupled per user. If 500 users monitor "AI", the backend executes 3,000 Serper searches and 9,000 Jina scrapes, repeating identical LLM clustering operations.

The Solution: Two-Stage Decoupled Pipeline

┌────────────────────────────────────────────────────────────────────────────────────────┐ │ STAGE 1: GLOBAL WORLD-STATE INGESTION & CLUSTERING (Nightly at 03:00 UTC) │ │ │ │ [HackerNews API] [GitHub Trending] [arXiv Preprints] [Curated RSS/Substack] │ │ │ │ │ │ │ │ └───────────────────┴──────────┬──────────┴─────────────────────┘ │ │ ▼ │ │ Raw Article Pool (500–1000 items) │ │ │ │ │ ▼ │ │ Deduplication & Local Embeddings (all-MiniLM-L6-v2) │ │ │ │ │ ▼ │ │ Groq / Qwen Clustering → 50–80 Canonical NewsClusters │ │ │ │ │ ▼ │ │ Pre-generate Base Cards & Core Deep Dives (Saved to DB) │ └─────────────────────────────────────────┬──────────────────────────────────────────────┘ │ ▼ ┌────────────────────────────────────────────────────────────────────────────────────────┐ │ STAGE 2: PERSONALIZED DELIVERY & MULTI-CHANNEL DISPATCH (Morning 06:30 Local) │ │ │ │ User Preference Vector (pgvector cosine similarity) │ │ │ │ │ ▼ │ │ Select Top 5–7 Clusters for Specific User │ │ │ │ │ ▼ │ │ Synthesize Custom Tone Super Summary (Groq) │ │ │ │ │ ▼ │ │ Generate 3-Minute TTS Audio (OpenAI / ElevenLabs) │ │ │ │ │ ┌───────────────────┬───────────┴───────────┬───────────────────┐ │ │ ▼ ▼ ▼ ▼ │ │ [Email Digest] [Mobile App] [Audio Brief] [Slack Bot] │ │ (Resend API) (Push + Cards) (Audio Stream) (Team Channel) │ └────────────────────────────────────────────────────────────────────────────────────────┘

3.2 Data Ingestion Matrix

  • Hacker News (Firebase API - Free): Top 30 stories extracted via official API. Yields human-filtered developer announcements and technical discussions.
  • GitHub API (Trending & Releases - Free): Tracks repo star spikes and release changelogs for key open-source packages.
  • arXiv & Hugging Face Daily Papers (Free): Captures AI/ML paper abstracts directly into the raw pool without web scraping.
  • Substack & Tech RSS (Free): Ingests 50+ curated high-signal industry feeds via Python feedparser.
  • Exa.ai / Serper (Neural / Web Search): Targeted semantic search queries for breaking news not captured by curated feeds.

4. Actionable Checkpoints for Google Antigravity IDE

The following checkpoints extend the initial 15 checkpoints in progress.md. They are strictly sequential and designed to allow Google Antigravity IDE to execute, refactor, and verify the codebase step-by-step.

Checkpoint 16: Multi-Source Ingestion Engine Backend Pipeline

Goal: Broaden data ingestion beyond Serper to include developer, research, and thought leadership streams.

  • Create backend/ingestion_sources/ module:
    • hn.py: Connect to Hacker News Firebase API (https://hacker-news.firebaseio.com/v0/topstories.json) and fetch top 30 stories.
    • github.py: Query GitHub REST API for trending tech repos and major release tags.
    • arxiv.py: Query arXiv API for latest AI/ML/CS papers.
    • rss.py: Parse high-signal Substack feeds using feedparser.
  • Unify output format: All sources map into standard RawArticle(title, url, source, content, published_at, tags) schema.
  • Verification: Unit tests in tests/test_ingestion_sources.py confirming data extraction from all 4 providers.
Checkpoint 17: Database Schema Migration & pgvector Integration Database

Goal: Equip PostgreSQL with vector capabilities and support team / multichannel delivery.

  • Enable PostgreSQL vector extension in Supabase / Alembic migration.
  • Update models.py:
    • Add embedding (Vector(384)) column to NewsCluster.
    • Add preference_embedding (Vector(384)) to UserPreference.
    • Create Team, TeamMembership, and SlackInstallation tables.
    • Add audio_url to SuperSummary.
  • Generate and apply Alembic migration scripts.
  • Verification: Script test_vector_db.py verifying vector insertion and cosine similarity queries (<=>).
Checkpoint 18: Stage 1 Global Clustering Pipeline Backend Pipeline

Goal: Transform ingestion from per-user to a single shared daily world-state pool.

  • Implement backend/pipeline_stage1.py:
    • Run all ingestion modules and aggregate into a daily raw pool (~500 articles).
    • Perform semantic deduplication using sentence-transformers (threshold 0.85).
    • Perform thematic clustering using Groq Qwen to produce 50–80 canonical NewsCluster records.
    • Calculate cluster centroid embedding and persist to DB.
    • Pre-generate base Cards and Deep Dives for each cluster.
  • Verification: Run pipeline_stage1.py locally and verify DB contains populated clusters with embeddings and pre-generated cards.
Checkpoint 19: Stage 2 User Matching & Personalization Engine Backend Pipeline

Goal: Deliver customized briefings to users in seconds using vector similarity.

  • Implement backend/pipeline_stage2.py:
    • For each active user, query DB for the top 5–7 NewsCluster records matching user.preference_embedding via pgvector.
    • Synthesize the user's custom daily SuperSummary using Groq, aligned with their configured tone bucket.
    • Create UserBriefing link records.
  • Measure performance: Verify stage 2 completes in <1.5 seconds per user.
  • Verification: Run matching test for 10 simulated users with divergent interests (e.g., Biotech vs LLM Infra) and verify personalized cluster assignments.
Checkpoint 20: Daily Email Digest Service (Resend Integration) Multi-Channel

Goal: Establish email as the primary daily retention anchor.

  • Integrate Resend Python SDK in backend/services/email_service.py.
  • Design responsive HTML email template:
    • Header: Personalized date & NewsBrief branding.
    • Lead: Daily Super Summary synthesis narrative.
    • Body: Top 3 Quick Cards with bullets and source links.
    • Call-to-Action: "Listen to 2-min Audio" & "Read Deep Dive".
  • Add user preference toggles in DB and API: email_digest_enabled, delivery_hour.
  • Verification: Send test briefing email to a verified mailbox and inspect HTML rendering on mobile/desktop clients.
Checkpoint 21: Daily Audio Briefing Engine (TTS) Multi-Channel

Goal: Provide a 2–3 minute audio mini-podcast for commuters and mobile listeners.

  • Implement backend/services/audio_service.py using OpenAI TTS (tts-1, voice nova/onyx) or ElevenLabs API.
  • Generate audio script summarizing the Super Summary narrative into a radio-style broadcast.
  • Convert text to MP3, upload to Supabase Storage / S3, and attach URL to super_summaries.audio_url.
  • Expose GET /briefing/today/audio streaming endpoint.
  • Verification: Generate sample audio and verify playback duration and voice clarity.
